# 无后端多租户配置中心

纯静态前端应用，用 IndexedDB 持久化、Web Worker 串行处理存储请求、BroadcastChannel 完成同源多标签页热更新，不依赖后端或构建工具。

## 启动

```bash
python3 -m http.server 5173
```

然后打开 http://localhost:5173 。模块 Worker 需要通过 HTTP 访问，不建议直接打开本地 HTML 文件。

## 能力映射

- 多租户隔离：编辑器和版本历史只读写当前 tenantId 的原始覆盖配置。
- 继承与覆盖：沿继承链从根到当前租户做对象深度合并；数组和标量作为叶子值由更近租户覆盖。
- 优先级：当前租户、父租户、祖先租户、全局租户。
- 热更新：发布或回滚后，Worker 通过 BroadcastChannel 广播；其他标签页立即更新预览和历史。
- 冲突检测：保存时校验基准版本，使用 base/local/remote 三方合并识别同路径并发修改和删除冲突。
- 冲突处理：支持载入远端、自动合并非冲突字段、强制覆盖。
- 回滚：从目标版本复制配置并追加新版本，历史版本不删除。
- 持久化：租户和每次 revision 都存入 IndexedDB，刷新页面后自动恢复。
- 租户切换：每个租户使用独立草稿，切换时不共享或覆盖编辑器数据。

## 验收步骤

1. 打开两个浏览器标签页。
2. 选择中国区 VIP，确认继承链为全局、中国区、中国区 VIP，品牌色继承中国区，beta 来自 VIP。
3. 在 VIP 修改 limits.maxMembers 并发布，另一个标签页即时出现更新提示且生效值改变。
4. 切换到其他租户再切回 VIP，确认各自草稿与历史互不串用，刷新后配置仍在。
5. 在两个标签页同时基于同一版本修改同一个字段并先后发布，第二个标签页应出现冲突；修改不同字段时点击自动合并。
6. 发布两个版本后点击旧版本的回滚按钮，系统会追加一个新版本且配置恢复为旧版本内容。
7. 新建租户并选择父租户，确认新租户从父链路继承配置。

## 代码结构

- index.html：管理控制台界面。
- js/db-worker.js：IndexedDB 初始化、事务、版本追加、回滚和广播。
- js/storage-client.js：主线程到 Worker 的 Promise 请求封装。
- js/config-utils.js：继承链、深度合并、差异和三方冲突检测。
- js/app.js：租户切换、即时预览、发布、热更新和回滚交互。
- tests/config-utils.test.js：核心合并和冲突算法测试。
